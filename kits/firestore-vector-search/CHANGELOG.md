- fix: the vector index created for `EMBEDDING_PROVIDER: openai` is now declared with 1536 dimensions instead of the extension's 512, so it covers the `text-embedding-ada-002` vectors the kit writes and `findNearest` works. The extension declared 512 while its OpenAI client was built with `dimension: 1536`, so its index never covered its own vectors and every query failed with `9 FAILED_PRECONDITION: Missing vector index configuration`; this is a deliberate divergence because there was no working behaviour to preserve. **Migration:** if an extension instance already created the 512-dimension index on your collection, delete it with `gcloud firestore indexes composite delete` before deploying. `createIndex` matches an existing index on the collection name and field path only, never the dimension, so it will keep the old 512 index and skip creation. See the README for the commands. Only the openai provider is affected.

The four `*_QUEUE_NAME` settings now take the deployed function name without that prefix

Vectors written by an earlier version of the kit are not comparable with the ones it writes now, so re-embed the collection after upgrading. The vector index for OpenAI was left at the extension's 512 dimensions at the time, which did not cover those vectors; it is 1536 now, see the entry above.
