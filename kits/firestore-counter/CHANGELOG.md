- fix: set `controllerCore`, `onWrite` and `worker` concurrency to `1` and ingress to `ALLOW_INTERNAL_ONLY`, matching the extension. Previously, the kit inherited the Gen2 defaults of concurrency `80` and ingress `ALLOW_ALL`. Existing kit deployments adopt these restrictions on their next deploy.

- fix: an Eventarc publish failure no longer fails the function. A channel that was deleted or is unreachable answers `PERMISSION_DENIED`, and the publish was awaited before the work the function exists to do, so the shard write was never aggregated. The publish failure is now logged as a warning and the invocation continues. Deploys also declare `eventarcpublishing.googleapis.com`, so the API is enabled on your project whether or not you use events.

- **BREAKING** feat: add the `DATABASE_REGION` parameter, which places the functions in the Cloud Run region derived from your Firestore database location. Regional locations pass through unchanged and the multi-region locations map to a region inside them (`nam5`/`nam7` to `us-central1`, `eur3` to `europe-west1`) instead of failing the deploy. Requires firebase-tools >= 15.28.0; with an explicit empty `DATABASE_REGION=` line in `.env` the functions declare no region and the Firebase CLI resolves one at deploy time, as before; omitting the line fails a non-interactive deploy. Changing the value on an existing instance deletes and recreates the functions. Upgrading an existing install: add `DATABASE_REGION` to your `.env`, either a value or an explicit empty line, before your next deploy, or the deploy fails on the missing parameter. Twelve of the offered locations resolve to a region with no Cloud Scheduler, which the scheduled `controllerCore` needs; the README lists them and says what to pick instead.
