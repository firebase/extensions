- **BREAKING** feat: add the `DATABASE_REGION` parameter, which places the function in the Cloud Run region derived from your Firestore database location. Regional locations pass through unchanged and the multi-region locations map to a region inside them (`nam5`/`nam7` to `us-central1`, `eur3` to `europe-west1`) instead of failing the deploy. Requires firebase-tools >= 15.28.0; with an explicit empty `DATABASE_REGION=` line in `.env` the function declares no region and the Firebase CLI resolves one at deploy time, as before; omitting the line fails a non-interactive deploy. Changing the value on an existing instance deletes and recreates the function. Upgrading an existing install: add `DATABASE_REGION` to your `.env`, either a value or an explicit empty line, before your next deploy, or the deploy fails on the missing parameter.
- fix: `VERTEX_AI_MODEL_LOCATION` left at its `null` default calls Vertex AI in the function's own region again, the extension's behaviour. The kit had passed no location, which sent the call to whichever region the SDK picked. Where the region cannot be read (the emulator, or library use outside a deployed function) the call goes to `us-central1`, or to `GCLOUD_LOCATION` if your environment sets one.
- fix: `ENABLE_DISCUSSION_OPTION_OVERRIDES` and `ENABLE_GENKIT_MONITORING` accept the extension's `yes` / `no` values again. The kit had declared them as boolean params, which only count the literal `true` as enabled, so a `.env` copied from an installed extension instance carried `yes` and silently left per-discussion overrides and Genkit monitoring off. Both are now the extension's labeled `Yes` / `No` selects and are read the same way the extension read them.
